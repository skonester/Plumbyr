# Plumbyr Architecture

- Pattern: Avalonia desktop (F#) + embedded payload pipeline + JSON rule loader + Node worker bridge.
- Key modules: `RuleLoader` (JSON→CleanTarget), `ScanEngine` (analyze/clean), `KuduBridge` (Node worker), `SystemInfo` (WMI/DXGI), `DriverService` (WMI/COM), `AppFiles` (embedded resource extraction to `%LOCALAPPDATA%/Plumbyr/runtime`).
- Lifecycle: `AppFiles.initialize()` → `RuleLoader.loadAllRules()` → `ScanEngine.AnalyzeTargets()` → `CleanTargets` → `CleaningHistory` DB.
- Extension: add JSON to `win32rules/`, rebuild; hook `ScanEngine` events; extend `KuduBridge` settings.
- Space map: `SpaceScanner` builds a read-only folder tree and bounded top-40 file list using an iterative, cancellable walk. `SpaceMapView` runs it on a background task and presents drive/folder selection, progress, breadcrumbs, size bars, and Explorer reveal actions. It is a separate `TreeMenu` page; closing the window cancels its scan.
- Sleep: `SleepController` owns monitoring, cancelable countdown/lid/wake timers, tool exclusion, pause/close recovery, and settings. `ISleepPlatform` isolates all Windows effects for tests. `SleepPlatform` serializes Kernel-Power events and native lid/suspend callbacks, restores retained process handles and device IDs, launches embedded Goodnight report scripts, and uses a separate journal-based recovery helper for unexpected exit. `SleepView` provides five tabs plus a sidebar countdown/cancel action through `MainWindow`. Normal launch is paused; the optional `PlumbyrSleep` sign-in task uses `--sleep-monitor`. Report collection is cancellable: `SleepWindowLifetime` requests process-tree cleanup on Close and retries window closure after completion. Process execution runs off the UI thread and bounds output-pipe draining; report text is batched to keep Close/Cancel responsive. Windows health tools and QuickOff must finish before normal close. Payload extraction and single-file deployment use the existing `AppFiles` pipeline.
